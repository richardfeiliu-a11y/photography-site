# Stage 2A — Cross-Research Evidence Synthesis

> 结论层；详细证据、冲突、H1–H11、偏差和 gaps 见 [STAGE_2_EVIDENCE_LEDGER.md](./STAGE_2_EVIDENCE_LEDGER.md)。本阶段不输出最终 IA。

## 证据边界

两套互不读取的 Stage 1 共纳入 59 个案例记录，仅 4 个网站重叠。低样本交集却产生多项相同模式，因此最有分量的不是某个网站，而是**不同样本独立复现的结论**。机构/社区案例只用于证明 metadata、facet、search、map 和规模可行性；艺术家项目站只用于证明 project integrity、sequencing 与 authored viewing。两者都不能单独代表 50–300 Gallery 的长期个人档案。

## 最强共同发现

| 综合判断 | Evidence strength | Stage 2B 边界 |
|---|---|---|
| **Gallery / Project / Series 是稳定的观看内容单元；一次旅行、拍摄、导入批次不天然等于一个 Gallery。** 两组均有多个艺术家与个人站支持。 | **High** | 进入 Stage 2B，但必须先定义 Gallery 的编辑边界。 |
| **Chronology 是成熟、耐久的发现维度，但不是所有摄影实践的一级导航。** Year-first 与 Project-first 都有多案例支持。 | **High** | 决定 primary / secondary，而不是争论“要不要时间”。 |
| **Place 可作为 metadata、facet 或导航，并可长期扩展；但不是成熟艺术摄影站的默认主轴。** | **High（可行性）／Medium（适用性）** | 先决定它服务检索还是观看，再决定可见层级。 |
| **同一内容可由 Time 与 Place 多入口访问而不复制。** 两组分别有 faceted archive、tag/post 与 dual-index 证据。 | **High（可行性）** | 可进入 Stage 2B；证据未证明双入口一定优于单入口。 |
| **公开的 Visit 层不是必要条件。** 两组都没有找到稳定成熟 precedent；现实中的多次访问常被 Project、时间桶、tag 或永久 Place 吸收。 | **High（反对“必须公开”）** | 不设为核心 IA 原则；是否保留内部 metadata 仍未决。 |
| **10–40 张不是可辩护的 Gallery 规则。** 真实内容单元从约 20 到 200+ 均存在。 | **High（反证）** | 删除固定阈值；改为由编辑意图、观看方式与性能共同约束。 |
| **Discovery 与 Viewing 是不同用户任务。** Index/facet/map 擅长找，sequence/slideshow/editorial 擅长看。 | **High（模式复现）** | 作为分析框架进入 Stage 2B，不把它宣称为唯一页面架构。 |
| **Map 在大型机构/社区 Archive 中成立，但对个人 curated Gallery 的优越性未被证明。** | **High（大型库可行性）／Low（本项目适用性）** | 不进入 MVP 默认项；只有明确空间检索任务时再评估。 |

## 最大冲突及其性质

最大冲突不是事实矛盾，而是**用户任务冲突**：Project-first 保护作者顺序与作品边界；chronology/place/facet-first 提升旧内容检索。两套研究都证明两端可行，却没有证明本项目应在何处取舍。Repeated Place 的 merge、split、theme、time-bucket 与 project absorption 也不是一条规则的胜负，而是“现实访问”与“摄影作品单元”并不等价。

真正的证据冲突很少：4 个重叠网站的观察基本一致；ICP 两边研究的是 Collection 与 Past Exhibitions 两个不同子系统。Ox Alpha 的案例索引头部仍写“无截图/27 cases”，但更新后的 `GAPS.md` 和截图目录证明已到 30 cases、43 PNG；这是文档版本漂移，不改变模式结论。Todd Hido 的移动截图只显示证书错误，不能作为 slideshow 的视觉验证。

## 明显变化的原始假设

- **保留但降级**：Chronology、Place、Minimal About 都有充分“可行性”证据，但不能升级为 universally primary / best practice。
- **保留并修改**：`Paris` 可是持久地点语义；是否需要独立 `Place(id=paris)`、可见 `Places → Paris`、以及 `Paris → Galleries` 是三项不同决策。
- **删除强表述**：公开 `Place → Visit → Gallery → Photo` 必需层级；Gallery 固定 10–40 张；Map 因大型档案成功就应进入个人站。
- **暂缓判断**：`Paris → Galleries grouped by year`、Homepage latest vs archive discovery、sequence + overview 是否双模式必需、Place 主导航还是 secondary index。

## Stage 2B 的证据边界

Stage 2B 可以基于以下事实继续：摄影应保持视觉主体；Gallery 是较稳健的策展/观看单元；Time 与 Place 可作为独立 metadata 和多入口发现维度；Visit 不应自动成为公开节点；发现界面与观看界面可承担不同任务。证据不能替产品决定：首页优先最新还是发现、Chronology/Place 的导航等级、Place 返回 Galleries 还是 Photos、Gallery 的编辑定义、viewer 是否双模式、公开 metadata 数量，以及 MVP 边界。
